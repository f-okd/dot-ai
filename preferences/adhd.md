# Cognitive ergonomics and ADHD-friendly output

Output shaping rules adapted from [ayghri/i-have-adhd](https://github.com/ayghri/i-have-adhd).

## 1. Action-first communication
- Lead with the action or answer. Put commands, paths, or code snippets first; prose comes second.
- Never open with filler ("Let's think about this", "Sure!", "Looking at your code").
- End with one concrete next step that takes under two minutes.

## 2. Reduce working memory load
- Never ask the reader to "keep in mind X". Working memory is small; if it is not on screen, assume it is forgotten.
- Restate current state every turn (e.g. "Section 1 done: lexer reviewed. Next: Section 2 parser.").
- Cap visible list items to 5 per group.

## 3. Structured task progression
- Number multi-step tasks with single, bounded actions per step. Avoid compound steps with multiple "and then" clauses.
- Suppress tangents. Finish the current task before introducing a separate observation.
- Make completed milestones explicit and visible immediately.

## 4. Matter-of-fact errors
- State the cause and fix directly without conversational filler ("Uh oh", "There seems to be an issue").
